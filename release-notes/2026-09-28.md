# Askalot Platform Release — 2026-09-28

This release is mostly about survey logic telling the truth when a respondent
changes their mind. Going back and changing an answer now leaves the survey in
the state that path actually produced, with no leftovers from the path that was
abandoned. Alongside that, the questionnaire editor explains more of what it
finds, and the conversation behind a project is visible to the people who work
on it.

## Highlights

- **Changing an earlier answer re-runs the survey from there.** When a respondent goes back and changes an answer, the questions that answer led to are re-evaluated. Answers the new path no longer reaches count as unanswered to every later condition, and variables are recomputed along the path that actually ran. A variable copied from a question the respondent skipped is treated as unknown rather than keeping its old value. Before, an abandoned branch could leave values behind that still steered later questions and appeared in the data.

- **Conditions decide only from the answers they have.** A condition that depends on a question the respondent left unanswered is no longer decided as if that answer were empty. Timing and provenance for an answer that fell off the path are kept out of the analysis data.

- **The questionnaire editor explains more of what it finds.**
  - A syntax error shows its line, column and the problem.
  - A condition on a combination of checkbox choices is analysed correctly, so a reachable question is no longer reported as unreachable.
  - Reading a variable where no assignment is guaranteed to have run is flagged as a warning.
  - A Roster's header names what it iterates over.
  - On/off labels on a switch read the same everywhere, whichever way they were written.
  - Crossing dependencies in the flow diagram are drawn in separate lanes, so they no longer overlap.

- **See the conversation behind a project.** The project page (for managers) and a study's overview (for analysts) now end with a read-only record of the AI conversation that shaped them, so the reasoning behind a design or an analysis stays with the work.

- **Errors appear where you are working.** Failures and confirmations are shown inline on the page, and in the platform's own dialog, instead of as browser pop-ups.

## Fixes & improvements

- **A campaign's assigned-user count is correct.** The edit page and the project's campaign list showed 0 assigned users whatever the campaign had. A campaign with targets but no completions yet now shows "0 of N completed" instead of a bare bar.
- **Calibration targets that match nothing are reported**, and outcome factors can no longer be edited from the campaign side, where a change would have gone unnoticed by the analysis.
- **An AI model configuration that mixes providers across reasoning levels is refused** when you save it, with the reason, instead of failing later during a run.
- **A sign-in refused because you belong to another workspace names that workspace**, and a reference document that could not be read is marked as unreadable rather than simply missing.
- **Re-indexing a reference document is faster**: unchanged passages are kept rather than processed again, and a document already being indexed is not indexed a second time.
- **Assistant tools page through datasets reliably**, returning a full page of the datasets you can see, and they reject an out-of-range page size up front.
- **The validation API says which copy of a questionnaire it checked.**
- **A sealed organisation can export its data** from every screen that offers an export.
- **Account emails name a mailbox that is answered.**
