# Askalot Platform Release — 2026-08-27

This release is mostly about honesty: several places where the platform finished
a job and told you it had gone fine, when it had not. A dataset that coded
nothing reported itself ready; a document whose text was missing said so only in
a log nobody reads; a long analysis was killed at the moment it would have
written its results. Each of those now says what actually happened, in the place
you were already looking.

## Highlights

- **Deleting a project no longer destroys unsaved work in an open design session.** A session workspace holds one project, and it is the only place an edit lives until you promote it — so removing the project's copy was not tidying up a duplicate, it was deleting the original. A delete now checks every open session first. Work that is already settled is removed as before; work that is not is moved to the same trash the project's own files go to, kept for the trash window, and the location is recorded. There is no project left to promote back into, so preserving the bytes and naming where they went is the whole of what can be saved — but it is no longer silently lost.

- **A long analysis is no longer cut off just before it produces anything.** The Analyst had a fixed time ceiling that sat inside the range healthy runs actually take: a run that finished in 21 minutes had a twin killed at 30, mid-work. Because results are written only when the run finishes, that kill landed on the one moment the run had something to save — half an hour of correct analysis, nothing kept. The Analyst now runs on a path that can be spoken to while it is still going, so it can be guided or wound up rather than only killed.

- **A dataset that coded nothing no longer reports itself as ready.** When the service that groups open-ended answers was unreachable, every question failed the same way, the derive produced no coded columns, and the result was marked ready with no error — indistinguishable from a dataset where you had simply chosen not to code anything. That case is now refused and named, and the distinction is kept: a question you never selected still codes nothing by design, and that is not a failure.

- **One question that cannot be coded no longer fails the whole dataset.** A single open-ended question with nothing codable in it used to take the entire derive down, and not cleanly — the job exhausted its retries and left the dataset spinning in "processing" until a background sweep flipped it, up to half an hour later. That question is now skipped and reported, and the rest of the dataset derives normally.

- **A brief outage no longer discards coding work you have already paid for.** If the progress channel dropped mid-round, the round exited without saving the categories it had already discovered — and the page simply stopped updating, with no error to explain it. The results are now kept whatever goes wrong around them, and the page closes the stream cleanly and reconnects rather than hanging.

- **A document whose text could not be extracted now says so where you would look for it.** Previously the only trace was an operator log line, so the failure mode was a researcher searching the workspace, finding nothing, and reasonably concluding the material was not there. A short notice now sits in the workspace naming the documents whose text is missing — and if one of your own documents happens to share that name, your document wins and is never overwritten.

- **Design sessions name the questionnaire you are working on.** The editor tab and the diagram panel beside it both used to show an internal filename; they now show the questionnaire's own title, from every path that opens them.

## Fixes & improvements

- **A dataset that lost a question's column now says which one, and why**, on the row itself — instead of leaving earlier numbers on screen with nothing indicating they refer to a column the export no longer contains.
- **An unavailable grouping service is reported once, in plain language, with the remedy that fits it** — rather than as a separate identical failure against every question, naming an internal address.
- **One question's own answers can no longer stall the questions behind it.** A question whose text the service rejected was reached first on every attempt, so everything queued behind it was unreachable rather than merely delayed. The round now distinguishes "the service is down" from "this question's answers were refused", and continues.
- **Weighting settings are now checked against the recipe the run actually receives.** Editing a coding selection or a weighting target while a derive was starting produced an unexplained error instead of a clear refusal naming the factor.
- **The derive no longer asks for an AI credential it never uses.** Setting the labelling method to "llm" made the derive demand a credential for a step that does not exist on that path, failing datasets that would otherwise have derived fine.
- **A failed AI run is now named as failed** rather than reported as a success with nothing to show.
- **A design session recovers an editor connection taken over by another window**, instead of refusing to start until someone intervened.
- **The number of design sessions running at once is now bounded by memory** rather than by a fixed count, so a busy period degrades predictably instead of exhausting the host.
- **The boundary around the design-session sandbox has been hardened.** No action is needed on your part, and no session behaves differently.
- **Document ingestion no longer shows a healthy badge** while the credential behind it is being refused.
- **The service that turns text into vectors is now checked to be the one the platform expects**, so a misconfiguration is reported rather than silently producing results in the wrong vector space.
