# Askalot Platform Release — 2026-08-18

## Highlights

- **Coding open-ended answers now gives you one labelled column per dimension, instead of a swarm of yes/no flags.** Previously every discovered cluster became its own binary indicator: three coded questions could turn into fourteen columns, each reading `Yes`/`No`, each carrying its meaning only in a slugified name like `q_p_q42c_independent_contracting_commercial`. A selected dimension is now a single categorical column with real value labels — the same shape a dropdown question produces, so every screen and export that already understood a dropdown understands this unchanged, and weighting can use it as one factor rather than a pile of flags.

- **You choose the dimensions before they become columns.** Candidate dimensions are proposed from the question text and a sample of the answers, and you review them in a two-pane screen. Only the ones you select become columns — the same set in the preview, in every export, and in weighting. An answer that matches no category reads `unclassified`, which is a real category you can weight on; a question nobody answered stays missing. Those two used to be easy to confuse, and they are now distinguishable everywhere.

- **A design session now belongs to exactly one project, chosen before anything opens.** You pick the project on a page that reserves nothing and builds nothing, so opening the designer and changing your mind leaves no trace. Only that project's files are on disk for the session — nothing else is reachable from the editor by search or quick-open, which is what makes "this session is working on this project" a fact rather than a convention.

- **Your work is proven saved before a session ends — or the session does not end.** Switching projects, closing the editor, and the automatic expiry sweep all pass through the same gate, and that gate is shaped as *prove it is settled, or refuse*. If a switch cannot confirm your edits are safely stored, it is refused and the session you were in is left exactly as it was. You are never put in the position of choosing between losing work and being stuck.

- **AI agents now work inside one organization at a time, and can move between them on their own.** An agent can see which organizations it is allowed to act in, see which one it is currently in, and switch — the same set of organizations you can reach yourself, no more. Everything it does afterwards happens in that organization, and the switch is remembered across restarts, so an agent no longer needs you to intervene to work somewhere else.

- **Read-only organizations can now be read.** An organization marked read-only previously could not be reached by an agent at all, which made archived work invisible rather than protected. An agent can now list and open the work inside one — projects, campaigns, questionnaires, respondents, datasets — while every attempt to change something is refused. That is what the setting was always meant to mean: completed work stays available and stays frozen.

    One exception, unchanged: **API tokens are closed entirely** in a read-only organization. You cannot generate one, and an existing one stops working. Browser sign-in and the AI-assistant connection are unaffected.

## Fixes & improvements

- **"Not found" now tells you which organization was searched.** An item belonging to a different organization used to be reported as simply missing, which reads exactly like something that was never created. The answer now names the organization it looked in, so a wrong-context answer is visible instead of quietly convincing.
- **A refusal to change a read-only organization now says so by name**, and is distinguishable from an item that does not exist or one you cannot reach.
- **A long-running agent session no longer expires early.** A session working in an organization reached through an administrator role was ended at its first renewal, because renewal asked a narrower question than the one that granted access in the first place. Both now ask the same question.
- **The number of coded columns now matches what the summary reports**, and a preview shows a category's label rather than the code stored underneath it.
- **Weighting targets can be set against a coded dimension's distribution**, rather than only against a single category at a time.
- **A design session left over from before this release is re-created cleanly** through the project picker rather than being guessed at.
- **Unused styles no longer ship in the interface stylesheet.**

## Correction — 2026-08-19

The note as first published said a read-only organization "is now readable and
simply refuses every change". That was true of the research paper and the
documentation tools, and **not** true of the project, campaign, questionnaire,
respondent, pool and dataset tools, which were still being refused when they
only read. The read tools now work as described. The highlight above has been
updated, and the API-token exception — which the original note omitted — is
stated with it.
