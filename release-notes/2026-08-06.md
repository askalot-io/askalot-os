# Askalot Platform Release — 2026-08-06

## Highlights

- **Weighting on answer-derived variables was silently doing nothing — this release fixes it.** When a weighting factor was built from an answer column (an outcome variable, or a category discovered by coding open-ended responses), every category lookup missed, every adjustment came out as 1.0, and the run reported success. The result was a weighted dataset whose weights were all identical — statistically the same as no weighting at all — while it was labelled as weighted and its distributions matched the unweighted data exactly. Factors built from demographic attributes were not affected. **If you have weighted on an outcome variable or a coded category, re-derive that dataset to get real weights**, and treat any weighted figures produced from one since July as unweighted until you do.

- **A mismatch between your calibration targets and your data now fails loudly.** The same class of problem could previously pass quietly. Where targets and data cannot be reconciled, the run now stops and says so, instead of returning a dataset that looks weighted and is not.

- **Multi-select questions can now be used as weighting factors, one option at a time.** Previously the raw multi-select column was refused — correctly, since every observed combination of options would have become its own weighting cell. The per-option columns are now offered as targets instead, so you can calibrate on "chose this option" as its own variable.

- **Your AI provider and model come only from your Profile Settings.** Askalot no longer falls back to a platform-chosen provider or model anywhere in document indexing and retrieval. What you select is what runs. If you have not configured a provider yet, the features that need one now tell you so directly, naming the setting to fill in — rather than quietly running on something you did not choose. Plain keyword and vector document search keeps working with no AI credentials at all; only the modes that actually consult a language model require one. Deleting your own documents is never blocked by an unset AI setting.

- **Test your AI connection before you depend on it.** Profile Settings gains a **Test connection** button that makes a real call to the model you have selected and reports what actually happened. A stored value is not the same as a working one — a revoked key, an expired session, a model your account cannot use, and an exhausted quota used to look identical until an AI run failed later with an error naming none of them. Each now comes back as its own verdict with the specific next step, and an expired session is distinguished from a bad credential so you are told to refresh rather than to re-enter something that was never wrong.

## Fixes & improvements

- **The AI Analyst is no longer cut off mid-analysis.** Its time budget had been inherited from an older, simpler analysis and was stopping healthy runs partway through synthesis — after the work had been done and moments before the report would have appeared. The budget is now sized to the analysis it actually governs.
- **Document searches are attributed to whoever ran them.** Retrieval now runs on the asking user's own configured provider, so usage is billed where it belongs rather than to a shared background identity.
- **Background maintenance no longer indexes documents on someone else's behalf.** A periodic sweep that finds an unindexed file now records it as needing attention — visible in your Documents panel, where you can index it on your own provider — instead of processing it under an unattributed account.
